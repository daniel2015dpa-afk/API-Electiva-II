# Activar el uso de Scripts # 

Cambiar la ejecutcion de scripts en powershell para poder ejecutar el node.js correctamente: 
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned (presionar Y si es ingles, S si es español)
Regresarlo a como estaba antes (política de windows): Set-ExecutionPolicy -Scope CurrentUser Undefined
Restrigirlo directamente: Set-ExecutionPolicy -Scope CurrentUser Restricted

# Crear el etorno virtual #

Manejo dos (venv de python y virtualenv como herramienta externa): para el venv normal no hay necesidad
de instalar algo adicional porque ya viene con python ese entorno. A diferencia de virtualen que es otra
herramienta externa que sirve para lo mismo pero si toca instalar.
pasos para instalar virtualenv - ubicarse en cd backend abrir la terminal y colocar este comando
"pip install virtualenv" existen varias opciones si no reconoce esa como:
"python -m pip install virtualenv" o "py -m pip install virtualenv"

ACTIVACION: para el venv es: cd backend y "python -m venv venv" o "py -m venv venv"
para el virtualenv es: cd backend y virtualenv venv o "python -m virtualenv venv" cuando no esta en el path
si no funciona con ese entonces seria "python -m virtualenv venv"

INICIALIZACION: para iniciar el venv de python solo hace falta estar en cd backend y colocar este comando
".\venv\Scripts\Activate.ps1"
para iniciar el virtualenv es igual a la venv es decir: ".\venv\Scripts\Activate.ps1"

nuevamente la opcion "variables de entorno..." se ingresa ahi, luego en la parte variables de usuario
para ... busca la opcion path y se ingresa a la opcion que dice editar, luego en el menu aparecen las
rutas se le da donde dice "nuevo" y se ingresa la ruta exacta de las variables que aun no estan, en
este caso me toco agregar "C:\Users\Danie\AppData\Local\Programs\Python\Python313\Scripts" para que
pudiera ejecutar la linea "virtualenv venv" y que se creara el entorno porque no lo estaba reconociendo
el path no sabia donde estaba, pero no es necesario, puedes directamente usar el comando "virtualenv venv"

PROBLEMAS DE COMPACTO EN CARPETAS: ctrl + , y luego escribir "compact folders y desmarcar la opcion que
dice "explorer: compact folders"

ELIMINAR CARPETAS (en este caso venv(virtualenv)): como esta backend el primer paso es "cd backend" y
luego "Remove-Item -Recurse -Force .\venv" (todo este proceso teniendo el venv desactivado: deactivate)

# activar el backend # 

se inicia la terminal; "cd backend" para ubicarse en esa carpeta, luego ".\venv\Scripts\Activate.ps1"
para activar el entorno virtual, luego "python -m fastapi dev main.py" o "fastapi dev main.py si ya
se tiene la ruta de scripts en el PATH (ambos funcionan con el fastapi[standard]), si falla esa se 
puede llamar a "python -m uvicorn main:app --reload" o aveces "python -m uvicorn main:app" ambos 
funcionan con la instalacion basica de fastapi ("pip install fastapi"), para detenerlo es "ctrl + c"

# activar el frontend #

se inicia la terminal; "cd frontend" para ubicarse en esa carpeta, luego "npm run dev" para iniciar
y para detenerlo "ctrl + c". si se quiere activar y iniciar la ventana "npm run dev -- --open" deja
la ventana iniciada en el navegador una ves el servidor este activo.

# AGREGAR PROYECTO A GIT Y GITHUB - COMMITS"

primero verificamos si git esta inicializado en la carpeta "git status" si marca error entonces se
inicia de 0 "git init" ya debe existir el archivo .gitignore para no agregar esa informacion, luego
"git add ." y si sale alguna advertencia de codigo LF (mac/linux) colocar este codigo "git config --global core.autocrlf input"
para decirle a git que no cambie el formato LF por el CRLF(windows) que trata del salto de lineas, luego 
"git commit -m "Primer commit del proyecto"" para guardar el estado actual, luego se ejecuta esta linea "git branch -M main"
para que force a la ramma a llamarse main que es lo normal actualmente (antes llamada master) luego conecta el repositorio Local
con el repositorio en el servidor de github con esta linea "git remote add origin https://github.com/tu-usuario/tu-repositorio.git"
obviamente reemplazando por los datos correctos, luego esta linea "git push -u origin main" para hacer el push (subir) los commits
hechos localmente al repositorio en github  

# ELIMINAR COMMITS Y DEVOLVERSE EN GITHUB #

"git log --oneline" para ver la lista de commits hasta ahora, luego se utiliza "git reset --hard <ID del commit al que quieres regresar>"
si los commits no se han subido a github con esa ya habra quedado listo todo, pero si ya estan en github, se utiliza este codigo
"git push origin main --force-with-lease" dependiendo del nombre de tu rama, si es main es ese mismo codigo, si es dev es
"git push origin dev --force-with-lease" para hacer esta eliminacion primero se debe hacer el reset al commit que quieres regresar.
